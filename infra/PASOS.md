# Qué hacer ahora, paso a paso

Orden real: cada paso depende del anterior. Lo que está **entre corchetes** es una decisión tuya;
lo demás es mecánico.

Al final de la parte 1 ya tienes dato cargándose solo cada noche. La parte 2 (la web) puede
esperar días o semanas sin que eso estorbe.

---

# Parte 1 · La ingesta  ·  *una hora, y queda funcionando*

## Paso 0 · La cuenta de AWS — 30 min

**Cuenta nueva, sólo para digivend.** Es la separación más limpia: ahí dentro no existe nada de
lo que ya tienes, ni puede existir.

### 0a · El registro

En la pantalla de alta, dos campos:

- **Root user email address**: un buzón que esté recibiendo correo **ya mismo**, porque AWS manda
  un código en segundos y toda la recuperación futura de la cuenta depende de él. Mejor un alias
  que pueda leer más de una persona (`aws@digivend.es`) que una dirección personal: si esa cuenta
  de correo desaparece algún día, recuperar el acceso a AWS es muy difícil.
- **AWS account name**: `digivend`. Es sólo una etiqueta y se cambia después.

Luego pide, por este orden: contraseña de root, tipo de cuenta, tarjeta, SMS y plan de soporte.

| pantalla | qué poner |
|---|---|
| Tipo de cuenta | **Business**, con el CIF. Así la factura sale a nombre de la empresa, no al tuyo |
| Tarjeta | Hace falta aunque no gastes. AWS retiene un euro para validarla y lo devuelve |
| Plan de soporte | **Basic — Free**. Los otros son cientos de dólares al mes |
| Si pregunta plan gratuito o de pago | **El de pago.** Suena al revés, pero el gratuito caduca a los seis meses o al agotar el crédito, y la cuenta deja de servir. Con el de pago sigues gastando sólo lo que uses y **los 100 $ de crédito se aplican igual** |

### 0b · Asegurar la cuenta, todavía como root

1. **MFA en la raíz.** `IAM → Security credentials → Multi-factor authentication → Assign MFA
   device`. La raíz lo puede todo, incluido cerrar la cuenta entera.
2. **Activar la facturación para usuarios IAM.** `Account → IAM user and role access to billing
   information → Edit → Activate`. **Es una trampa clásica**: sin ese interruptor, un usuario con
   permisos de administrador sigue recibiendo «acceso denegado» en facturación, y no podrías crear
   el aviso de gasto del paso 0d.

### 0c · El usuario con el que vas a trabajar

`IAM → Users → Create user`.

| campo | valor |
|---|---|
| User name | `Gabriele` |
| Provide user access to the console | sí |
| Console password | **Autogenerated** |
| Require password reset | sí |
| **Set permissions** | **Add user to group → Create group** |
| Nombre del grupo | `Administradores` |
| Política del grupo | **`AdministratorAccess`** |

**Comprueba en la pantalla de revisión que aparece `AdministratorAccess`.** Si sólo ves
`IAMUserChangePassword`, no has puesto permisos: eso lo añade AWS solo por marcar el cambio de
contraseña, y con eso el usuario no puede ni abrir CloudFormation.

Un grupo en vez de pegarle la política al usuario, porque cuando haya una segunda persona la
metes en el grupo y se acabó, y retirar el acceso es una sola acción.

Al crearlo, **descarga el `.csv`**: la contraseña autogenerada se enseña **una sola vez**. Ahí
viene también tu URL de acceso, del tipo `https://<id-de-cuenta>.signin.aws.amazon.com/console`.

Cierra sesión, entra con `Gabriele`, cambia la contraseña, y **ponle MFA también a este usuario**.
A partir de aquí no vuelves a usar la raíz.

### 0d · Dos ajustes antes de empezar

1. **Un presupuesto con aviso.** `Billing and Cost Management → Budgets → Create budget`, tipo
   coste, 50 € al mes, alerta al 80 % a tu correo. Si algo se desmadra te enteras el mismo día y
   no a fin de mes.
2. **La región: `eu-west-1` (Irlanda)**, arriba a la derecha. Todo el proyecto vive ahí. La única
   excepción de todo el despliegue es el certificado del paso 8, y está avisada.

## Paso 1 · Bajar el repositorio a tu ordenador — 2 min

CloudFormation no lee de GitHub: hay que subirle el fichero. Y de paso necesitarás otros cinco
en los pasos 3 y 4, así que se baja todo de una vez.

1. Abre **https://github.com/gabriello83/flightdeck**
2. Arriba a la izquierda, donde pone el nombre de la rama, **cambia a `claude/trusting-goldberg-selqz6`**.
   Es donde está todo esto; en la rama principal todavía no.
3. Botón verde **Code → Download ZIP**.
4. Descomprime. Lo que vas a usar está todo en la carpeta `infra/`.

> **El error que hay que evitar**: abrir el fichero en GitHub y guardar la página con *Guardar
> como*. Eso guarda la página web de GitHub, no el fichero, y CloudFormation la rechaza con un
> error de formato que no explica nada. Si bajas ficheros sueltos en vez del ZIP, usa siempre el
> botón **Raw** primero.

## Paso 2 · Crear la pila — 10 min

`CloudFormation → Create stack → With new resources (standard)`.

### Pantalla 1 · Create stack

| campo | qué elegir |
|---|---|
| Prepare template | **Choose an existing template** |
| Template source | **Upload a template file** ← *no* «Amazon S3 URL* |
| Choose file | `infra/plantilla.yaml` del ZIP |

Al elegir el fichero, la consola lo sube sola a un bucket suyo y rellena la URL. **Next.**

### Pantalla 2 · Specify stack details

**Stack name**: `digivend-ingesta`

Y ocho parámetros. **Déjalos todos como vienen menos el último**:

| parámetro | valor | qué es |
|---|---|---|
| `Prefijo` | `digivend` | el nombre de todo lo que se crea. Cambiarlo levanta una instalación entera aparte |
| `Proyecto` | `digivend` | la etiqueta de coste |
| `VenCloudEndpoint` | *(viene puesto)* | la API de VenCloud |
| `VenCloudEmpresa` | `2311` | |
| `HoraCarga` | `cron(15 3 * * ? *)` | las 3:15, hora de Madrid |
| `HoraRecalculo` | `cron(45 4 * * ? *)` | las 4:45, hora de Madrid |
| `DiasRetencionLog` | `30` | cuánto se guardan los registros |
| **`AvisoCorreo`** | **tu correo** | **el único que tienes que escribir.** Si lo dejas vacío no se crea la alarma y una noche puede fallar sin que te enteres |

**Next.**

### Pantalla 3 · Configure stack options

No toques nada. Si quieres, en **Tags** añade `Proyecto` = `digivend`: se propaga a todo lo que
cree la pila. **Next.**

### Pantalla 4 · Review and create

Baja del todo. Hay un recuadro con una casilla:

> ☑ *I acknowledge that AWS CloudFormation might create IAM resources with custom names.*

**Márcala.** Hace falta porque los roles llevan nombre propio —`digivend-rol-extraccion`,
`digivend-rol-agregados`— en vez de uno generado al azar, precisamente para que se vea de quién es
cada cosa en la lista de IAM. Si no la marcas, la creación falla al instante.

**Submit.**

### Qué esperar

Tres minutos, con la pestaña **Events** refrescándose. Al final, `CREATE_COMPLETE` en verde.

Si sale **`ROLLBACK_COMPLETE`**, no se ha creado nada y no hay nada que limpiar: busca en Events
la primera línea en rojo, que es la causa real, y pásamela.

Ve a la pestaña **Outputs** y **apunta `NombreBucket`**. Será algo como
`digivend-vending-123456789012`. Lo necesitas en los pasos 4 y 9.

## Paso 3 · El token de VenCloud — 2 min

`Secrets Manager → Secrets → digivend/vencloud/token → Retrieve secret value → Edit`.

Elige **Plaintext** y pega **sólo el token**: sin comillas, sin `Bearer`, sin espacios ni saltos
de línea al final. Guarda.

Va aquí y no en una variable de entorno de la Lambda para que no aparezca a la vista de
cualquiera que abra la configuración de la función, ni en una captura de pantalla.

## Paso 4 · Los dos ficheros de configuración — 3 min

`S3 → el bucket del paso 2 → Create folder` → nombre `config` → Create.

Entra en `config/` y **Upload → Add files** con los dos:

- `infra/manifiesto.json`
- `infra/perfiles.json`

Tienen que quedar exactamente en `config/manifiesto.json` y `config/perfiles.json`. Si quedan en
la raíz del bucket, la extracción no los encuentra y se para nada más empezar.

## Paso 5 · El código de las dos Lambdas — 10 min

**Las dos van en zip, ninguna se pega.** Pegar en el editor de la consola parece más cómodo y
no lo es: con cuatrocientas líneas el navegador puede truncar el pegado, y el error que sale
luego es un fallo de sintaxis a mitad del fichero que **no apunta a la causa**. Ya nos pasó.

Prepara los dos zips de una vez:

```bash
sh infra/empaquetar.sh
```

Deja `paquetes/extraccion.zip` y `paquetes/agregados.zip` (y de paso los de la web, para el paso
12). Si no tienes `sh` a mano, se hacen a mano:

- **`extraccion.zip`**: una copia de `infra/lambda_extraccion.py` **renombrada a `index.py`**, y
  nada más. El nombre importa: el handler de esa función es `index.lambda_handler`.
- **`agregados.zip`**: `lambda_agregados.py` y `reglas.py`, con sus nombres.

En los dos casos, **los ficheros van en la raíz del zip, no dentro de una carpeta**.

Y se suben igual: `Lambda → la función → Code → Upload from → .zip file` → el zip → **Save**.

## Paso 6 · La primera carga, a mano — 5 min + espera

`Lambda → digivend-extraccion → pestaña Test → Create new event` (cualquier nombre, el JSON
`{}` vale) → **Test**.

Tarda varios minutos: son 30 informes por 4 días cada uno.

## Paso 7 · **Mirar el registro. Este es el paso que importa** — 10 min

`S3 → el bucket → registro/extraccion/anio=…/mes=…/` → abre el JSON del día.

Busca `"filas"` en las entradas de `"ok"`:

| lo que ves | qué significa |
|---|---|
| `"filas": 3504` y números parecidos | **Perfecto.** La respuesta se entiende y el dato está |
| `"filas": null` pero `"bytes"` con miles | La descarga fue bien y **lo que no entiende es mi lector**. Pásame el JSON y lo arreglo: son diez líneas |
| entradas en `"errores"` | Mándame el mensaje. Si dice `HTTP 404`, el número de informe de ése no es el que creíamos |

**El dato crudo ya está guardado en `crudo/` pase lo que pase**, porque se graba antes de
intentar interpretarlo. Ninguna noche se pierde por un error de lectura.

## Paso 8 · Los agregados — 3 min

Sólo cuando el paso 7 esté limpio: `Lambda → digivend-agregados → Test → {}` → **Test**.

Comprueba en S3 que aparecen `cabina/interno/panel.json` y `cabina/cli-airbus/panel.json`.
Ábrelos: si las cifras te cuadran con lo que ya sabemos, **la ingesta está terminada**.

A partir de aquí va sola: extracción a las 3:15 y agregados a las 4:45, hora de Madrid.

# Parte 2 · La plataforma web  ·  *cuando quieras*

## Paso 9 · [El certificado] — 10 min de trabajo, horas de espera

Es lo único con plazo, así que conviene empezarlo pronto aunque el resto espere.

`Certificate Manager`, **y aquí sí cambias de región: `us-east-1`**. Es la única excepción de
todo el proyecto, y es porque CloudFront sólo acepta certificados de ahí.

`Request certificate → Request a public certificate` → nombre **`dashboard.digivend.es`** →
validación **DNS**.

- Si el DNS de `digivend.es` está en **Route 53**: hay un botón *Create records in Route 53*. Un clic.
- Si está en **otro registrador** (IONOS, GoDaddy, Arsys…): ACM te da un `CNAME` con nombre y
  valor. Hay que crearlo a mano ahí y esperar. **Esto es lo que puede tardar horas.**

Cuando pase a `Issued`, copia el **ARN**.

## Paso 10 · La pila web — 10 min

`CloudFormation → Create stack` → **`infra/plantilla-web.yaml`**. Vuelve a `eu-west-1`.

| parámetro | qué poner |
|---|---|
| `BucketDatos` | el `NombreBucket` del paso 2 |
| `RemitenteAvisos` | una dirección verificada en SES, para las alarmas por correo |
| `Dominio` y `CertificadoArn` | **déjalos vacíos de momento** |

Marca otra vez la casilla de IAM con nombres propios.

Dejarlos vacíos no es pereza: la plataforma funciona igual en la URL que da CloudFront, y el
dominio se añade después **sin tocar una línea de código**, porque la página no tiene ningún
dominio escrito dentro. Así no esperas al certificado para ver si funciona.

Apunta de Outputs del paso 10: `UrlProvisional`, `BucketWeb`, `Tabla`, `PoolUsuarios`.

## Paso 11 · La clave del asistente — 2 min

`Secrets Manager → digivend/asistente/clave-anthropic` → pega la clave de la API de Claude.

Sin ella **el asistente no funciona y el resto de la plataforma sí**. Si todavía no la tienes,
sáltate este paso y vuelve luego.

## Paso 12 · El código de las tres Lambdas — 10 min

```bash
cd infra/api
zip api.zip comun.py autorizacion.py lambda_api.py
zip alarmas.zip comun.py autorizacion.py lambda_alarmas.py

mkdir -p paquete && pip install anthropic -t paquete/
cp comun.py autorizacion.py lambda_asistente.py paquete/
cd paquete && zip -r ../asistente.zip . && cd ..
```

Sube cada zip a su función: `api.zip` → `digivend-api`, `alarmas.zip` → `digivend-alarmas`,
`asistente.zip` → `digivend-asistente`.

El del asistente pesa unos megas porque lleva el SDK; los otros dos son de kilobytes, porque sólo
usan biblioteca estándar.

## Paso 13 · El primer administrador — 10 min

Es **el único alta que no se puede hacer desde el panel**, porque todavía no hay nadie con quien
entrar. Tres cosas:

**a)** `Cognito → digivend-usuarios → Users → Create user`. Correo el tuyo, marca *Mark email
address as verified*, y pon una contraseña de 12 caracteres con mayúscula, minúscula y número.

**b)** `DynamoDB → Tables → digivend-plataforma → Explore items → Create item → JSON view`, y crea
**dos** elementos. El primero:

```json
{ "pk": {"S": "PERFIL#interno"}, "sk": {"S": "FICHA"},
  "dato": {"S": "{\"nombre\":\"Serunion\",\"tipo\":\"admin\",\"sesiones\":[],\"permisos\":{}}"} }
```

El segundo, **cambiando el correo por el tuyo** (en minúsculas, las dos veces):

```json
{ "pk": {"S": "USUARIO#tu.correo@serunion.es"}, "sk": {"S": "FICHA"},
  "dato": {"S": "{\"nombre\":\"Gabriele\",\"perfil_id\":\"interno\",\"estado\":\"activo\",\"asistente\":true}"} }
```

Las comillas escapadas del campo `dato` son a propósito: dentro va un texto que contiene JSON.

**c)** Sube la página: `S3 → el bucket `digivend-web-…` → Upload` del contenido de `app/consola/`
y `app/airbus/`.

## Paso 14 · Entrar — 2 min

Abre la `UrlProvisional` del paso 10. Entra con tu correo y la contraseña del paso 13a. Te pedirá
cambiarla: es de un solo uso.

Desde dentro ya puedes crear el perfil de AIRBUS y sus usuarios sin volver a tocar la consola de
AWS.

## Paso 15 · El dominio, al final — 5 min + propagación

Un `CNAME` de `dashboard.digivend.es` al nombre que da la salida `DondeApuntaElDns`. Después,
`CloudFormation → la pila web → Update stack → Use existing template`, y rellena `Dominio` con
`dashboard.digivend.es` y `CertificadoArn` con el del paso 8.

# Lo que no es tuyo, es mío

Cuando termines el paso 7, pásame el registro y **cierro el único hueco que queda** en todo el
sistema: la forma exacta de la respuesta de `GetReportV2`.

Y queda pendiente enchufar las dos páginas a la API: hoy el acceso de la consola es un prototipo
que no valida contraseñas, y el orden de los paneles se guarda en el navegador en vez de en el
servidor. El backend ya está; es trabajo mío, no tuyo.
